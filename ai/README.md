# AI layer: MCP server + skill

Two ways to make a coding agent know the whole Arc library — all 233 Pro items *and* the 147 free
ones — instead of guessing component names.

| | Official (uiarc.dev) | This repo |
| --- | --- | --- |
| Skill | `npx shadcn@latest add @uiarc/arc-skill.json` → 13 files, **free items only** in `components.md` | `ai/skill/arc-pro/` → same 13 files, catalogue regenerated over **380 ids** |
| MCP | remote `https://uiarc.dev/api/mcp`, **sign-in required**, Pro source only on a paid plan | `ai/mcp/server.mjs`, stdio, **no account**, source for every item |
| Pro source | gated (`403 Sign in with Pro access to view this source`) | local: `src/components/arc/<id>/` |
| Pro playbooks | `GET /api/skills` → `403 Sign in with Pro access to download Pro skills`, 7 playbooks | `ai/skill/arc-pro/pro/` — authored here, same six workflows |

Both are built from the same data the site itself serves: `public/docs/<id>.md` (docs, props,
keyboard, a11y, motion, responsive), `src/data/catalog.json` (groups, tiers) and the reconstructed
source.

## Install

```bash
cd ai/mcp && pnpm install && cd ..    # once: @modelcontextprotocol/sdk + zod
node ai/install.mjs                    # no flag: list what each flag writes
node ai/install.mjs --claude           # this repo: .mcp.json + .claude/skills/arc-pro (relative symlink)
node ai/install.mjs --all              # claude + claude-user + cursor + vscode + codex + agents
node ai/install.mjs --print            # raw JSON for the server and the codex TOML block
```

The repository is the only data source at runtime: `ai/mcp/server.mjs` and the skill read
`src/components/arc/**` and `public/docs/*.md`, nothing else. `node scripts/sync-free.mjs` re-checks the
free half against the public registry (dry run by default, `--apply` writes only missing files and never
overwrites drift).

`ai/install.mjs` merges into existing config files instead of replacing them, prints every path it
writes, and can be re-run safely. It resolves the server path from its own location, so the repo can be
moved, and the project symlink is relative so a clone works at any path.

## MCP server

```bash
node ai/mcp/server.mjs          # stdio, newline-delimited JSON-RPC
```

Dependencies live in `ai/mcp/package.json` (`@modelcontextprotocol/sdk`, `zod`). `ai/mcp/pnpm-workspace.yaml`
marks the folder as its own package root, so this install is self-contained and never touches the app's
lockfile:

```bash
cd ai/mcp && pnpm install
```

### Tools

| Tool | Input | Returns |
| --- | --- | --- |
| `search_components` | `query`, `kind?`, `tier?`, `group?`, `limit?` | ranked ids with the reason to use each and the reason not to |
| `list_components` | `kind?`, `tier?`, `group?`, `limit?`, `offset?` | ids, or the 55 groups with counts when unfiltered |
| `get_component` | `id`, `include: docs\|source\|both`, `section?` | the item docs (when to use, usage, API reference, keyboard, a11y, motion, responsive) and its files |
| `get_install_command` | `ids[]`, `target: repo\|external` | the shadcn command for free items, the copy recipe for Pro |
| `get_skill` | `file` | any file of `ai/skill/arc-pro/` |

Search expands intent (`kpi`→metric, `delete`→destructive, `dashboard`→overview, …), requires one
strong hit plus most query words, and returns the "not for" line so the agent can follow the docs
instead of fighting them.

### Wiring

Claude Code:

```bash
claude mcp add arc-pro -- node "$PWD/ai/mcp/server.mjs"     # add --scope project to share via .mcp.json
```

Cursor (`~/.cursor/mcp.json`), Codex (`~/.codex/config.toml` under `[mcp_servers.arc-pro]`) and
VS Code (`.vscode/mcp.json`) take the same pair:

```json
{ "mcpServers": { "arc-pro": { "command": "node", "args": ["/absolute/path/to/uiarc/ai/mcp/server.mjs"] } } }
```

## Skill

`ai/skill/arc-pro/` is generated by `node ai/build.mjs` from `ai/skill-src/` plus the catalogue:

| Path | Contents |
| --- | --- |
| `SKILL.md` | front matter `name: arc-pro`, workflow, 13 principles, never-do list, quick decisions, playbook router, file index |
| `INSTRUCTIONS.md` | the always-on rules block for `AGENTS.md`, `CLAUDE.md` or `.cursor/rules` (13 always / 8 never) |
| `components.md` | all 380 ids grouped, tier marked, with the link to each group file |
| `catalog/<group>.md` | 55 files: per item summary, when to use, when not to use, keywords, files |
| `pro/*.md` | the six Pro playbooks plus `PRO.md`, the router and shared ground rules |
| `design.md`, `copy.md`, `motion.md`, `accessibility.md`, `responsive.md`, `composition.md`, `checklist.md`, `example-*.md` | the free skill prose, verbatim |

The Pro playbooks are authored here because the site gates the originals: `full-page-generation`
(brief → region plan → build → verify), `design-system-generation` (token layer, contrast table in both
themes), `refactor-to-arc` (region-by-region parity), `motion-recommendations` (inventory → tokens →
delete), `responsive-optimization` (five widths, measure → fix → re-measure), `accessibility-audit`
(ranked findings with patches).

`ai/skill/arc-pro/` is a normal agent skill folder (front matter `name: arc-pro` in `SKILL.md`):

```bash
node ai/install.mjs --claude        # link into .claude/skills for this repo
node ai/install.mjs --claude-user   # copy into ~/.claude/skills for every project
node ai/install.mjs --agents        # copy into ~/.agents/skills
```

- `INSTRUCTIONS.md` — paste into `AGENTS.md`, `CLAUDE.md`, or use as `.cursor/rules/arc.mdc`
  (`node ai/install.mjs --cursor` writes exactly that file).

## Data

| Path | What |
| --- | --- |
| `ai/data/index.json` | 380 items: id, title, kind, group, tier, summary, keywords, deps, use/avoid bullets, sections, files, sizes |
| `src/components/arc/<id>/` | the source of every item: 233 reconstructed Pro dirs plus 146 free dirs copied verbatim (`src/components/arc/blocks/<id>/` for the free blocks) |
| `src/data/free-items.json` | manifest of the free items: id, title, type, categories, files, per-file sha256 prefix |
| `ai/build.mjs` | regenerates `ai/data/index.json`, `ai/skill/arc-pro/components.md`, `catalog/` and `pro/` |
| `ai/install.mjs` | writes client configs and installs the skill |
| `ai/mcp/smoke.mjs` | asserts the tool surface and ten intent rankings |

Rebuild after adding an item:

```bash
node ai/build.mjs
```

## Limits

- `get_component` truncates source at 160k characters per call; larger items are cut with a note and
  the file paths are listed so the agent can read them from the repo.
- Search is lexical plus a synonym table, not an embedding index: it ranks by id, title, keywords,
  summary, "when to use" and group. `list_components` is the fallback when intent wording is unusual.
- `login` is a variants landing page on the site (5 blocks), so it has docs but no source of its own;
  the individual variants (`sign-in`, `login-centered`, `signup-form`) are separate items.
